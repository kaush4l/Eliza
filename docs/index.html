Hermes Live — WASM edition

The Hermes Agent on Alpine Linux, booted in your browser by container2wasm (Bochs x86_64). The model never enters the VM: every API call the agent makes is relayed out by this page and streamed back token by token, so inference runs at your machine's native speed. The terminal below is the real hermes TUI — click it and type.
LLM:
Connecting your LLM

Hermes needs an OpenAI-compatible, tool-calling model server on this machine — omlx, LM Studio, Ollama, llama.cpp server…

  1. Start it with CORS allowed for this page. LM Studio: Developer tab → Enable CORS. Ollama: launch with OLLAMA_ORIGINS=*.
  2. Enter its base URL above and hit Test — it lists the models; pick one. If the browser asks to allow local network access, allow it.
  3. Reload to apply a URL or model change after the VM has started.

On the hosted (https) page, Chrome gates local-network requests. Loopback is exempt from mixed-content rules, but Local Network Access is a separate permission: the first call to 127.0.0.1 is blocked (net::ERR_FAILED, the agent then sits waiting) until you allow it — address-bar icon → Site settings → Local network access → Allow, then reload. Two alternatives that need no permission: serve this same docs/ directory yourself (python3 serve.py 8917, then open http://127.0.0.1:8917/), or point the LLM field at a remote OpenAI-compatible endpoint over https.

State: ~/.hermes (sessions, memories, skills) and ~/work are sealed with AES-256 under a browser-local passphrase and stored in this browser (Cache API), then restored on the next boot. Nothing leaves your machine. Saving is on demand: click Save state.

URL overrides: ?backend=<url> · ?model=<name> · ?guest=shell boot to a shell instead of hermes · ?persist=0 amnesia boot · ?image=<url> load an unchunked .wasm.
